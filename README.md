# Homey app for "Bear" blind and awning automation

  <img src="drivers/blind/assets/images/large.png" alt="5 channel Bear remote">

<br>

Control Bear outdoor blinds and awnings from Homey, by emulating the 5-channel 433 MHz Bear remote.

What works:

* Up, stop and down, on Homey's native blind control.
* A position slider: ask for 40% and Homey runs the motor for as long as 40% takes.
* Each of the remote's five channels as its own device.
* Pairing learns your own handset's address, so the app controls only *your* blinds.
* Homey follows the physical remote, including the ALL button, and keeps the position with it.
* Flow cards for up, stop, down and position, generated by Homey from the standard blind
  capabilities, plus a **Recalibrate** card of this app's own.

## Position

The motors send nothing back, so Homey does not read the position, it counts it: when a motor
started, which way it went, and how long a full run takes.

* Opening and closing are timed separately, because gravity helps one direction and fights the
  other.
* Asking for 0% or 100% never gets a timed stop. The command goes out and the motor's own limit
  switch decides where it lands, which resets the count exactly. Most days include a full open and
  a full close, so this happens without anyone doing anything.
* Partial moves are where the count drifts. Homey tracks how far out it might be, and past about
  15% of full travel the next move to an intermediate position runs to the nearer end stop first
  and times the rest from there. The **Recalibrate** flow card forces that on demand.
* Handset presses are decoded off the air and counted the same way, including one left to run into
  an end stop.

It cannot notice an obstruction, a wind sensor retracting an awning, or a command the motor missed.
If a blind moves without Homey hearing about it, the position is wrong until the next run to an end.

## Pairing

Homey learns which motors to talk to by listening to your existing remote. When adding a device,
hold the handset near Homey and press any button. Homey captures the remote's address and offers
all five channels; tick the ones you want.

Then calibrate each blind: **Device → Settings → Maintenance → Try to Repair** walks you through
three runs and times them, so you do not have to guess at the travel times or hold a stopwatch
yourself. Everything the wizard measures can also be typed in by hand in device settings, along
with:

* **Stop sent early by** — how far ahead of the calculated moment the stop goes out, covering the
  delay between handing a frame to the radio and the motor acting on it. Raise it if the blind
  overshoots, lower it if it stops short.
* **Invert the position** — by default 100% is fully open, which is Homey's own convention. Turn
  this on to read 100% as fully out instead. It changes only the number; up is still up.

## Protocol

The 433 MHz protocol was reverse-engineered from captures made with Homey's built-in RF signal
recorder. See [RF_PROTOCOL.md](RF_PROTOCOL.md) for the frame layout, the decoded tables, and how to
capture and decode additional commands.

## Development

```bash
npm test
homey app validate --level verified
homey app run
```

`app.json` is generated from `.homeycompose/` by `homey app build` and committed; `npm test` fails
if the two drift apart.
